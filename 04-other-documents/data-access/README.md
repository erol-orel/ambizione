## Sequence

1. **Send the request email** (`01-request-email.md`) with the one-page project note
   (`02-project-note.md`) attached. Ask for a support letter, not for the data itself — the data
   comes later, under ethics.
2. **Send them a draft letter** (`03-support-letter-template.md`). People sign drafts; they
   rarely write letters from scratch.
3. **Start the CCER submission** in parallel (`04-ethics-note.md`). Being the applicant on your
   own ethics submission is evidence of independence, and the reviewers will ask about the
   platform's security posture — which is why the hardening comes first.

## What you are actually asking for

Be precise, because vagueness is what stalls these requests. For each dataset:

- **Retrospective extract**, aggregated to daily counts — no individual-level clinical data
  needed for WP3. This is a much easier ask than it first appears and you should say so early.
- **Period**: `[[from ~2015 to present — specify what exists]]`.
- **Variables**: date; count; a coarse category (`[[respiratory / cardiac / trauma / other]]`);
  and for ICU, occupied and available beds. `[[Confirm what is realistically extractable.]]`
- **No direct identifiers, no free text, no addresses.**

Ask explicitly whether a daily aggregate extract avoids the need for individual-level data
approval. If it does, say so in the research plan — it materially lowers the feasibility risk a
referee perceives.

## If a partner hesitates

The fallback in WP3 is real and you should be willing to say so: the cold-start hypothesis can be
tested on open surveillance series plus the Legionella linkage. Saying this out loud makes the
request easier to grant, because it removes the implication that the whole project depends on
them. It is also true, which is the main thing.
